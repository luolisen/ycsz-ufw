# YCSZ 软件自保护方案

状态：驱动源码、固定协议和用户态维护路径已实现；尚未完成 WDK 编译、签名、加载或隔离 Windows 动态验收。2026-09-12。

## 约束和现状

用户要求保留现有 Windows 账户、权限、系统策略、联想智能云教室及网络环境，不通过降低学生账户权限实现验收。本轮只修改仓库文档，不操作生产端环境。先前 STU01 验证中的“改为标准账户”建议不再作为实施方案。

现有 Ycsz.exe 同时承载 UI 与 LocalSystem 服务；Program.cs 的 HostService 接受 Stop，安装器服务 ACL 允许管理员停止服务，程序目录允许 Administrators 完全控制。仓库尚无内核驱动工程。因此 SYSTEM、目录隐藏和服务异常重启均不足以宣称满足当前管理员账户下的自保护要求。

## 官方参考与适用边界

- [微软 ObCallback 示例](https://learn.microsoft.com/en-us/samples/microsoft/windows-driver-samples/obcallback-callback-registration-driver/) 演示通过驱动限制进程句柄访问，使示例进程不能被终止，并提供解除保护入口。这证明软件自保护路线可行，不是本产品已具备该能力。
- [句柄访问权限文档](https://learn.microsoft.com/en-us/windows-hardware/drivers/ddi/wdm/ns-wdm-_ob_pre_create_handle_information) 列出可限制的 PROCESS_TERMINATE 等权限。需要覆盖创建及复制句柄，不能把保护仅建立在程序名称上。
- [文件系统过滤驱动](https://learn.microsoft.com/en-us/windows-hardware/drivers/ifs/about-file-system-filter-drivers) 能观察或阻止文件系统请求，适合作为本产品文件保护的实现基础；进程保护本身不提供文件防删除。
- [反恶意软件受保护服务](https://learn.microsoft.com/en-us/windows/win32/services/protecting-anti-malware-services-) 要求 ELAM 驱动以及匹配的服务和模块签名，不能作为普通 C# 程序直接可用的权限开关。暂不选作 YCSZ 实施路线。
- [Deep Freeze 官方介绍](https://www.faronics.com/reboot-restore-software) 描述重启恢复基线。重启恢复与运行时阻止终止、删除是不同验收项，不据此推断其私有进程保护实现，也不在联想镜像平台上叠加新的磁盘还原层。
- 本次未找到足以确认极域内部自保护技术的官方材料，不声称其使用某个特定驱动接口。

## 拟采用的软件架构

1. 将托盘入口与核心服务职责明确分离。核心策略不得依赖托盘存活。若要求托盘自身也不能被任务管理器结束，必须把合法启动的托盘实例纳入保护，而非仅在退出后重新拉起。
2. 增加经过正式签名的最小自保护驱动，限定保护本产品经过身份验证的进程。设计进程实例生命周期校验，避免 PID 重用和同名程序误保护。内核接口不能接受任意管理员提交任意 PID 后予以保护的通用指令。
3. 使用文件系统 minifilter 保护本产品程序和必要配置，设计覆盖删除、重命名、替换、截断和写入的规则，并处理路径别名、重解析点和硬链接。正常日志写入、策略持久化及升级必须有明确授权路径。先在隔离环境审计匹配范围，再启用阻断。
4. 停服是独立路径：即使阻止 TerminateProcess，SCM 正常 Stop 仍可能让服务自行退出。需要设计经应用认证的维护状态，默认保护期间拒绝非维护停服；不要仅移除任务管理器的终止权限就标记通过。
5. 教师维护通过已有应用身份认证，进入限定操作和期限的维护窗口；升级、卸载与恢复均有可审计路径。不能仅按进程名或“具有管理员身份”放行，也不能把管理密码明文传入驱动或打包进安装器。
6. 保护状态必须真实可见：分别显示驱动是否加载、进程保护是否注册、文件过滤是否生效。缺少签名或驱动加载失败时明确提示“自保护未启用”，不能显示成功。

这是待实现设计，不承诺防御离线磁盘修改、任意内核代码或所有管理员操作。

## 交付门槛与风险

[微软内核签名要求](https://learn.microsoft.com/en-us/windows-hardware/drivers/install/kernel-mode-code-signing-requirements--windows-vista-and-later-) 是生产交付前提。需要可用的 WDK 构建链、适合目标系统的正式驱动签名渠道及隔离 Windows 验证机；这些条件尚未核实，不能通过关闭系统安全检查绕过。

驱动可能造成蓝屏、文件访问死锁或与联想过滤驱动冲突，故必须先进行驱动验证、重启及维护恢复测试，再安排部署。安装本产品驱动本身属于软件更新，不等于零系统变更；当前用户禁止改变生产环境，因此本设计不代表已获准部署驱动。

## 2026-09-11 独立实现进度

- `src/Ycsz.Core/SelfProtection.cs` 已实现用户态协议模型和维护状态机：固定服务/映像身份、PID 与启动时间字段、映像 SHA-256、实例 nonce、三项能力状态、有限维护租约及过期自动关闭。协议不传管理密码，也不接受任意进程名或任意 PID 作为保护授权。
- `src/Ycsz.App/Program.cs` 会把当前状态明确显示为“内核自保护未启用：驱动未构建或未加载”；托盘恢复、SCM 重启和网络进程扫描不会被写成拒绝终止的证据。
- `src/Ycsz.Tests/Tests.cs` 覆盖驱动不可用、能力不完整、伪造身份、维护授权、过期关闭和可逆恢复。该部分是可运行的用户态状态机测试，不是驱动加载测试。
- 尚未添加默认安装的驱动。真实 Ob callbacks/minifilter 工程仍需 WDK、驱动验证、正式签名和隔离 Windows 靶场；在这些条件具备前不得安装、加载或发布驱动。

## 2026-09-12 实现更新

- `drivers/YcszProtection/` 现在包含可交给 Windows WDK 的 x64 minifilter 工程、INF、共享协议头和实现源。Ob callback 同时覆盖新建与复制的进程句柄，并按 `PEPROCESS`、PID、创建时间及内核解析映像路径绑定目标；minifilter 保护安装根目录的变更操作。
- `src/Ycsz.Core/SelfProtectionDeviceTransport.cs` 对接固定 IOCTL 和 x64 结构布局；`HostService` 在启动时尝试激活当前固定安装路径的实际服务实例，缺少设备时保持失败/未启用状态。`src/Ycsz.App/Ui.cs` 通过已登录本地 IPC 暴露限时维护入口，服务侧在完整进程/文件能力激活时暂不接受普通 SCM Stop。
- 驱动未实现 `ServiceStop` 能力位；SCM 停止保护依赖已认证的服务生命周期门禁，必须在隔离 Windows 上验证 SCM 行为，不能把 `CanStop=false` 或异常恢复当作驱动拒绝终止证据。
- 当前协议只固定一个安装根目录，因此 `ProgramData\\YcszFirewall` 的配置、日志和基线仍依赖 ACL/应用恢复，不属于本轮 minifilter 已覆盖的防删除范围。
- 用户态 mcs/csc 兼容构建与 57/57 隔离测试已通过；本机无 WDK，故驱动仍未编译、签名、安装或加载。INF 的 altitude `385200.1234` 是占位值，正式运行前必须申请唯一 altitude、生成 CAT 并使用适配目标系统的正式签名。
