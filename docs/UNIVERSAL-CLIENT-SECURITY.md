# 通用客户端、提权边界与反破坏验证

版本：v0.2.0 工程预览。测试仅针对本仓库和一次性 Windows 测试环境。

## 交付行为

管理端的“生成通用客户端包”导出 ZIP，包含客户端专用安装器和加密 client.ycsz。先解压全部文件，再安装；一份包可重复用于多台机器，客户端名称来自 Environment.MachineName。每台机器生成独立随机 ID 和 256 位随机凭据，同名机器也不会合并。

通用包中的共享凭据只允许注册新设备，不能当作已存在设备的心跳凭据。客户端先将新身份用 DPAPI 保存为 pending-enrollment.bin，再发起注册；响应丢失后重试不重置策略或重复占用名额。成功初始化后删除 pending 文件。旧单设备注册包仍可读取。

最多 64 台设备、32 个通用包，沿用原设备数上限。“停用通用接入包”停止全部旧包的新注册，不影响已安装设备；“撤销接入”仍针对特定设备。已安装配置不应克隆到另一台电脑。

## 攻击面与验证步骤

| 攻击面 | 可复现步骤 | 预期结果与边界 |
| --- | --- | --- |
| 服务控制 | 标准用户分别申请 SERVICE_STOP、SERVICE_CHANGE_CONFIG、DELETE 权限 | Windows 返回 Access Denied；授权管理员保留控制能力 |
| 服务进程 | 标准用户申请运行中 LocalSystem 服务的 PROCESS_TERMINATE 句柄 | 返回 Access Denied，不实际终止服务 |
| 安装文件 | 标准用户尝试以写权限打开 Ycsz.exe、System.ps1 | 拒绝访问；不能将服务加载文件替换为自己的代码 |
| 配置凭据 | 标准用户尝试读取 settings.bin | 拒绝访问；文件内容另有 LocalMachine DPAPI，不能将 DPAPI 单独视为访问控制 |
| 本地管理 IPC | 不带会话、伪造会话、正确密码、注销后复用会话 | 未授权拒绝；密码授权允许；注销后拒绝 |
| 服务身份校验 | 代码追踪 Ipc.VerifyServiceEndpoint | 发密码前将管道对端 PID 与 SCM 的服务 PID 比对；本次未运行管道抢占实测 |
| 共享接入包冒用 | 同包注册两台；尝试用共享 token 发设备心跳、替换已有设备 token | 两台独立；冒用/替换拒绝 |
| 撤销和重复注册 | 对同一 ID 重试，撤销后再次注册，停用接入包再注册 | 正常重试幂等；撤销不可通过旧身份恢复；已停用包不能新增设备 |
| 计算机名称 | 认证心跳改变机器显示名称，再重启服务读取 | 名称更新且持久化，设备内部身份不变 |
| 进程检测 | 只启动测试程序的 v2ray.exe 和 safe-fixture.exe 两个无害副本；调用生产 ProcessScanner | 前者被终止并报告，后者继续运行；按名称匹配仍可被改名规避 |
| SCM 恢复 | 管理员只终止刚创建的一次性管理服务，最多等 30 秒 | SCM 自动拉起新 PID；设备、撤销、名称仍保留 |
| UAC | 检查安装器 RequestExecutionLevel admin 与 Program.RequireAdmin | 安装/恢复/卸载操作要求管理员；GUI asInvoker 不等于服务降权 |

## 执行方法与范围控制

本机逻辑测试：`./scripts/build.sh`。Windows：`./scripts/build.ps1`，随后在一次性虚拟机运行 `./scripts/Test-Security.ps1 -DisposableVm`。GitHub-hosted Windows runner 由工作流自动启用。

Test-Security.ps1 在已有 YcszFirewall 服务、配置目录或 TCP 17443 监听存在时拒绝执行。它复制本版程序到独立 Program Files 子目录，从生产 NSIS 中提取服务创建/配置命令并编译测试安装器，创建合成管理配置与临时标准用户，运行真实权限、IPC 和回环 TLS 检查，最后清理仅本次创建的资源。不会在用户正在使用的管理端上替换服务，不运行 WFP 白名单或网卡修改。

- v0.1.0 安装与密码登录已在实际管理主机验证，见 INSTALLER-RECOVERY-2026-09-11.md；不将该证据当作 v0.2.0 完整实机验收。
- Windows Server 2022 GitHub-hosted runner 验证完成：[运行 34515610735](https://github.com/luolisen/ycsz-ufw/actions/runs/34515610735)，代码提交 ab73ede。原生编译、44/44 逻辑测试、2/2 真实 TLS、9/9 隔离网络逻辑、PowerShell 语法、NSIS 打包和安全集成均通过。
- 安全集成日志共 36 条 PASS（初始化 1、NSIS/服务配置 2、权限/注册/导出/进程 29、SCM 重启 1、重启后持久化 3）。完整输出保存在 artifacts/security-results-windows.txt；日志仅从 Windows UTF-16 转为 UTF-8 并移除行尾空格，测试数据与结果不改写。
- 本次发布使用该 CI 构建的 Windows 安装包，服务夹具实际加载其中同一次构建的应用；不把本地 Mono 重编译产物替代为已实测的二进制。
- 早期 CI 发现 NSIS 使用 POSIX 路径导致 Windows 打包找不到文件；改用 NSIS 跨平台支持的反斜杠后通过，没有关闭 Defender。

## 风险说明与未验证项

1. 防破坏针对标准用户。Windows 管理员、SYSTEM、内核级工具及离线磁盘修改超出此保护边界；保留合法管理员恢复路径。
2. 通用接入包及密码的持有者可尝试占用设备配额。包泄露应停用旧包并生成新包。撤销某设备并不能阻止持包的合法本机管理员清除配置后以新身份重新安装。
3. 命名管道单连接及登录全局退避可被本地用户利用造成可用性下降；超时和退避不等于完全防 DoS。没有据此宣称提权成功或凭据泄露。
4. 本次 Windows 权限和服务恢复检查复用生产服务配置；完整客户端 WFP 阻断、重启前后规则、网卡/代理真实回滚和客户端异常恢复事件上报仍需双机可回滚靶场验收。仅有一台管理主机时不将其改成受控客户端。
5. 共享 CDN IP 的域名串用、代理进程改名、被删除第三方网卡驱动不能自动重建等原有边界保持不变。
6. 安装器和程序未进行商业代码签名。没有关闭或绕过系统安全产品来使 CI 通过。
