# YCSZ 0.1.0 Windows 用户测试清单

测试对象：客户端和管理端，使用同一个安装包，在安装时选择角色。

当前状态：已完成 macOS 上的编译、核心逻辑、模拟网络逻辑、回环 TLS 和安装包内容检查；尚未验证真实 Windows 安装、界面、服务、WFP 拦截及网络回滚。本文所有 Windows 项目均为待测，不代表已通过。

## 1. 测试准备

- 至少两台 Windows 10/11 x64 测试机或虚拟机：管理端 M、客户端 C1；有条件增加 C2，验证单机策略不会影响其他客户端。
- 安装 .NET Framework 4.8，使用系统自带 Windows PowerShell 5.1。
- 三台机器处于同一测试局域网，网络配置文件为“专用”或域网络；管理端使用固定 IPv4。默认管理通信端口为 TCP 17443。
- 为虚拟机保存快照。客户端应能通过本地控制台操作，不能仅依赖远程桌面进行网络修改测试。
- 安装前确认网络、DNS、网卡及 hosts 正常；首次安装会将其保存为基线。
- 准备一个 Windows 管理员账号和一个普通学生账号；软件管理密码与 Windows 账号密码是两回事。
- 首轮先做 T01–T08、T10、T13、T15；网络破坏性测试放到第二轮，每次只改变一项。
- 工程预览包尚未代码签名；如系统或安全软件阻止安装，记录提示，不要全局关闭安全防护。

安装文件：`Ycsz-Setup-0.1.0-x64.exe`

## 2. 先保存应急恢复方法

发生断网且无法从管理端解冻时，在客户端本地以管理员身份打开 PowerShell：

```powershell
& "$env:ProgramFiles\YcszFirewall\Ycsz.exe" --recover
```

预期：服务停止，本产品出口规则移除，相关审计设置恢复。此操作不会自动恢复所有 IP、DNS 或 hosts 配置；必要时用安装前记录或虚拟机快照恢复网络。服务仍保留，之后启动服务或重启系统可能重新应用策略。

**仅结束进程或停止服务不等于解除拦截**：出口规则具有持久性。恢复命令只清理本产品规则，不应清空其他防火墙规则。

## 3. 测试项目

每项记录“通过 / 失败 / 未测”；不适用需说明原因。先确认基本接入成功，再测拦截功能。发生失败时保留现场和日志，不要连续修改多项配置。

### T01 管理端安装与密码

1. 在 M 运行安装包，选择管理端，设置至少 12 字符的本地管理密码。
2. 输入不一致的两次密码，确认不能完成初始化；改为一致后继续。
3. 从开始菜单打开管理界面，尝试错误密码，再使用正确密码。
4. 关闭界面后重新打开。

预期：安装成功；密码错误无法进入；每次重新打开均需验证；管理端界面可正常显示。连续输错后存在延迟，等待约 65 秒再尝试，记录是否仍无法登录。

### T02 注册与客户端安装

1. 在 M 点击“注册客户端”，填写 C1 名称、M 的固定 IPv4、至少 12 字符的注册包密码，导出 `.ycsz` 文件。
2. 保持 M 在线，在 C1 安装并选择客户端，设置 C1 本地管理密码，导入注册包。
3. 先试错误的注册包密码，应拒绝；再使用正确密码完成安装。
4. 等待 30–60 秒，在 M 刷新，检查 C1 在线状态和设备名称。
5. 如有 C2，单独生成它的注册包并安装，不要复用 C1 注册包。

预期：两端接入成功，设备可区分；注册失败时不应出现“已成功接入”的误报。客户端初始化需要实际连接管理端，离线安装失败应显示明确原因。

### T03 已安装状态只读检查

将交付 ZIP 解压，在其包含 `scripts` 的目录中，以管理员 PowerShell 执行（M、C1 分别执行）：

```powershell
powershell.exe -NoProfile -ExecutionPolicy Bypass -File .\scripts\Test-Windows.ps1 -Mode Installed 2>&1 | Tee-Object -FilePath .\windows-check.txt
```

预期：7 项检查均 PASS：服务运行、服务身份和路径、可见卸载入口、数据目录权限、受保护配置文件、可执行文件格式、服务故障恢复配置。

此脚本只读，不修改网络。它不验证实际拦截、密码加密强度或数字签名；其中“PE signature”是文件格式标识，不是代码签名。脚本位于交付 ZIP 内，不在软件安装目录内。

### T04 托盘入口与普通用户权限

1. C1 注销并用普通学生账号登录，检查托盘图标。
2. 若图标未出现，记录问题，并可用普通权限运行下列命令继续测试：

```powershell
& "$env:ProgramFiles\YcszFirewall\Ycsz.exe" --tray
```

3. 普通左键点击托盘，再按住 Shift 左键点击，尝试错误和正确的软件密码。
4. 用普通用户尝试停止 `YcszFirewall` 服务、修改安装目录文件和 `C:\ProgramData\YcszFirewall` 配置文件。

预期：Shift+左键弹出密码界面；错误密码不能进入；普通用户不能停止服务或修改受保护文件。安装完成后未立即出现托盘不等于自启动失败，应以重新登录结果为准。

补充：开始菜单也有受密码保护的管理入口；合法 Windows 管理员能够执行恢复和服务管理，这是当前设计行为。

### T05 代理进程检测、结束与上报

无需安装真实代理工具。可在 C1 的临时测试目录，用 Windows PowerShell 5.1 生成一个仅等待、不联网的测试程序：

```powershell
$fixtureDir = Join-Path $env:TEMP ('YcszFixture-' + [Guid]::NewGuid().ToString('N'))
New-Item -ItemType Directory -Path $fixtureDir | Out-Null
$fixtureExe = Join-Path $fixtureDir 'ycsz-safe-test.exe'
Add-Type -TypeDefinition 'public class YcszFixture { public static void Main() { System.Threading.Thread.Sleep(300000); } }' -OutputAssembly $fixtureExe -OutputType WindowsApplication
Start-Process $fixtureExe
```

1. 未命中名称的 `ycsz-safe-test.exe` 应保持运行，最长 5 分钟后自行退出。
2. 复制为目标名称并启动，例如：

```powershell
Copy-Item $fixtureExe (Join-Path $fixtureDir 'v2ray.exe')
Start-Process (Join-Path $fixtureDir 'v2ray.exe')
```

3. 观察约 10 秒，确认目标进程退出；等待 30–60 秒，在管理端确认对应事件。
4. 每次只测一个名称，完整覆盖下表；另测 `XRAY.EXE` 大小写。

### T06 用户代理与系统代理

1. C1 Windows 设置 → 网络和 Internet → 代理，开启手动代理，地址设为 `127.0.0.1:18080`。
2. 等待约 30–60 秒，重新进入页面查看，确认被关闭并上报。
3. 分别测试“使用设置脚本”（测试地址可用 `http://127.0.0.1:18080/test.pac`）和“自动检测设置”。每次单独开启。
4. 管理员 PowerShell 测 WinHTTP：

```powershell
netsh winhttp set proxy 127.0.0.1:18080
# 等待 30–60 秒后执行：
netsh winhttp show proxy
```

预期：恢复直接访问，无代理；管理端收到事件。检查的是当前已加载用户配置和系统代理，不能据此证明尚未登录用户的配置也已处理。

### T07 hosts 修改与恢复

1. 用管理员权限编辑 `C:\Windows\System32\drivers\etc\hosts`，在末尾添加 `127.0.0.1 ycsz-test.invalid`，保存。
2. 等待约 60 秒，重新读取文件。

预期：该测试行消失，文件内容恢复为安装基线，管理端有事件。随后在快照环境选测删除 hosts 文件，预期能按基线恢复。不要在未留备份时删除真实业务条目。

### T08 出口白名单、拒绝与事件

1. 准备两个可控测试网站 A、B，使用**不同服务器 IP**，提供 TCP 80 或 443；安装前确认客户端均能访问。没有这类测试站时标记本项未测，不用一次公共网站访问失败代替证明。
2. M 在“统一白名单”加入 A 的 IP，确保 B 的 IP 和域名不在名单，点击“下发至所有客户端”。
3. 等待客户端策略应用后，C1 新建请求访问 A 和 B。例如系统提供 curl.exe 时：

```powershell
# 将占位内容替换成真实测试地址，分别执行：
curl.exe --noproxy "*" --connect-timeout 10 -I http://A的IP/
curl.exe --noproxy "*" --connect-timeout 10 -I http://B的IP/
```

4. 使用域名条目重复验证；若有原生 IPv6 环境，再分别测试 IPv6 放行和拒绝。

预期：A 有实际 HTTP 响应，B 连接被阻断，管理端收到拒绝连接事件。页面缓存不是放行证据；HTTP 404/405 仍说明已连接到服务器。仅 B 超时还不够，必须与安装前及解冻后的可达性对照。

注意：网站默认放行端口为 TCP 80/443，不是任意端口；UDP 443/QUIC 不在此放行范围。拒绝事件主要记录进程、目标 IP、端口，不保证显示完整网址；同类事件有去重，不要求每次点击都新增一条。

### T09 单客户端解冻与重新冻结

1. 接 T08，在 M 选中 C1 点击“解冻出口”，等待应用，再访问 B。
2. 如有 C2，确认 C2 仍无法访问 B。
3. C1 解冻期间，再执行一次 T05 或 T06。
4. M 对 C1 点击“冻结出口”，使用新连接访问 B。

预期：仅 C1 可以访问 B；C2 策略不受影响；C1 进程、代理、网络基线防护继续生效；重新冻结后 B 被拒绝。

### T10 管理端暂时离线与恢复上报

1. 关闭 M 测试机或断开 M 的测试网络，不改变 C1 的网络配置。
2. 在 C1 触发一次 T05 和 T07，记录时间。
3. 恢复 M，等待约 60 秒并刷新。

预期：C1 离线期间继续执行最后策略，重新接入后补报事件。只做少量事件测试，当前离线队列有容量限制，不承诺无限保留。

### T11 未授权网络变化回滚（第二轮）

在有快照和本地控制台的 C1，每次改变一项，恢复成功后再继续：

1. 修改 DNS。
2. 修改静态 IPv4 地址或默认网关。
3. 添加测试静态路由。
4. 禁用现有测试网卡。
5. 添加一块虚拟网卡，改变网卡协议绑定或创建测试网桥。

预期：通常观察 60 秒，慢机延长至 120 秒；发现变化并尝试恢复基线，上报对应事件；新增 IP 网卡被禁用。要对照实际配置和连通性，不能只看到“恢复”日志就算成功。

已知边界：被删除的硬件、驱动无法自动重建；新增网卡并非自动卸载。不要将卸载网卡驱动列为“必须自动恢复成功”。DHCP 正常续租得到不同地址不应被误判为手工修改。

### T12 授权修改基线及失败回退（第二轮）

1. C1 管理界面选择“编辑所选设备基线”，先仅新增一条无业务影响的 hosts 注释，保存申请。
2. 等待应用，确认注释保留，后续扫描不会恢复为旧版本。
3. M 选中 C1，通过同一编辑入口修改；若有 C2，检查其配置未变化。
4. 重启 C1，确认已批准配置保留。
5. 快照环境选测：由 M 下发会导致 C1 无法连接 M 的错误网络配置，观察是否退回旧基线并恢复接入；最多观察 120 秒，失败则用本地控制台恢复并记录。

预期：成功应用后实际配置和基线一致；错误配置不能被错误标记为成功。同一失败版本不会无限重复执行，修正后需重新保存产生新版本。

“接纳当前网络为基线”是另一个本地授权入口；测试时记录是否与自动回滚发生竞争或界面超时，不要靠反复点击掩盖问题。

### T13 服务崩溃恢复与开机启动

1. 在 C1 管理员 PowerShell 查询服务及其 PID：

```powershell
Get-CimInstance Win32_Service -Filter "Name='YcszFirewall'" | Select-Object Name, State, ProcessId, PathName
```

2. 核对路径是本产品且 PID 非 0，再在任务管理器“详细信息”中只结束该 PID，模拟服务异常退出。不要按名称一次结束全部 `Ycsz.exe`。
3. 观察 60 秒，重新查询服务，检查恢复运行且 PID 变化；在 M 检查异常恢复事件。
4. 重启 C1，普通用户登录，检查服务、托盘、管理端上线、冻结策略。

预期：异常退出后自动恢复，重启后无需学生手工启动。服务控制台的正常“停止”操作不是崩溃测试，两者预期不同。

### T14 管理员应急恢复

1. 确认 B 正被阻断，执行第 2 节 `--recover`。
2. 检查服务停止，重新请求 B；检查其他自有 Windows 防火墙规则仍存在。
3. 如要继续测试，以管理员启动 `YcszFirewall` 服务，确认策略重新应用。

预期：本产品规则清理成功；在其他网络条件允许时 B 恢复访问；不是清空系统全部防火墙配置。

### T15 卸载与退出（最后执行）

1. 在 C1 管理界面点击“卸载本机软件”，先输入错误的软件管理密码，取消。
2. 确认软件和服务仍在，策略继续工作。
3. 使用正确密码完成卸载，再检查服务、托盘自启动、安装目录和本产品规则已清理，网络恢复预期访问。
4. M 最后卸载；另一个快照分支可测试“程序和功能”卸载入口，同样需要权限和密码。

预期：错误密码不能卸载；正确卸载无遗留出口锁定。当前版本有可见的系统卸载入口；不会隐藏自身。`C:\ProgramData\YcszFirewall` 配置和日志会保留，这不是卸载失败。重新做首次安装请还原干净快照，避免旧配置影响基线采集。

## 4. 已知缺口，不能勾为完全验收通过

- **严格域名隔离尚未实现**：域名解析成 IP 后放行，同 IP/CDN 上的其他域名可能也能访问。即使 T08 通过，也不等于“仅能访问指定网站”完全达成。
- 默认域名仅为候选名单，未逐项完成官方备案核验，不代表“全部简中备案网站”的完整目录。
- 不承诺恢复已卸载驱动或已移除硬件；不绕过 UAC，不阻止合法 Windows 管理员执行应急恢复。
- 安装包尚未签名；Windows 实机结果尚待本轮验证。
- 证书冒充、畸形协议帧、命名管道抢占、磁盘写满、安装中断、休眠及 BFE 重启等开发级故障测试另见 `SECURITY-VALIDATION.md`，不要求首轮由用户全部完成。
