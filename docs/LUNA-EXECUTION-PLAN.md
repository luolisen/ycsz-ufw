## 阶段一：可交付的异常恢复

1. 审查 src/Ycsz.App/Program.cs、Ui.cs、installer/Ycsz.nsi、scripts/Update-Installed.ps1。已有 SCM failure actions：5 秒、10 秒、30 秒重启；已有每会话托盘 Mutex。复用这些机制。
2. 新增服务侧托盘生命周期管理。使用 Windows 支持的交互会话 API，以目标登录用户的普通令牌启动固定安装路径的 `Ycsz.exe --tray`，不要将 SYSTEM GUI 放进用户桌面。检查活动交互会话、已存在的真实托盘实例和启动冷却，避免多实例、会话 0 启动及崩溃重启风暴。API 失败记录节流日志，不能让核心防护服务跟着退出。固定程序路径和参数，禁止变成任意程序提权启动接口。会话退出与服务停止时正确释放线程、token、进程句柄。
3. 从服务生命周期启动/停止监督器。异常杀托盘后恢复，服务被杀后由 SCM 恢复并重新接管托盘。正常教师维护停止时不得再拉起。不要增加互相无限拉起的第二套服务。
4. 修正 `--close-ui`：现有实现按路径杀全部 Ycsz，可能包含服务。确认服务停止才允许维护关闭 UI，明确排除会话 0 服务进程，不能成为停服捷径。更新脚本回滚路径也要 Stop + Wait + Close UI 后再覆盖旧文件，避免新托盘占用文件。
5. 对安装器与原位更新的 SCM 恢复配置作一致性检查。必要时让更新脚本修复本产品配置，但本轮只编辑，不在生产机执行。
6. 增加可注入的会话/启动抽象和必要逻辑测试，覆盖缺失实例恢复、已有实例不重复启动、会话退出、启动失败退避、停止竞争、正常维护不恢复。先沿现有 mcs/csc 编译方式构建到临时目录，不覆盖已交付 artifacts。

## 阶段二：防破坏组件开发

1. 基于 SELF-PROTECTION-DESIGN 明确最小驱动工程、用户态控制协议和维护状态机；使用官方 Ob callbacks / minifilter 接口。进程防终止、SCM 正常停服、文件删除覆盖分别处理。
2. 驱动只接纳经过验证的本产品实例，处理 PID 重用、句柄复制、并发卸载、文件别名/重解析点等边界；不按可伪造的进程名简单放行。维护授权不得仅凭“管理员身份”成立，否则不能满足现有账户模型。

## 验收与证据

| 攻击面 | 隔离测试 | 成功标准 |
| --- | --- | --- |
| 托盘异常退出 | 结束已核验路径和会话的测试实例 | 限定时间内新 PID，只有一个实例，核心服务未变 |
| 服务异常退出 | 结束专用测试服务 | SCM 限定时间内新 PID，配置身份保持 |
| 正常维护 | 停服、升级失败回滚、卸载 | 不被监督器重新拉起，文件可正常替换 |
| 进程保护 | 非提升及提升工具请求终止测试进程 | 终止失败且原 PID 存活，不能用换 PID 算通过 |
| 文件保护 | 对专用测试文件删除/重命名/覆盖 | 操作失败且内容哈希不变 |
| 兼容性 | 会话切换、注销、重启、联想同版本测试镜像 | 无蓝屏/死锁/重复托盘，名称网络与平台行为保持 |

优先现有便携测试与专用 Windows CI/可恢复 VM。Windows 动态测试必须拒绝已有产品配置/服务的机器，禁止把生产机作为靶场。CI 无交互桌面时明确记录托盘实际交互测试未执行，不用 mock 结果替代。

## 2026-09-12 本轮实现状态

- 已加入 `drivers/YcszProtection/` 最小 WDK 工程：共享固定布局控制协议、Ob callbacks 进程句柄限制、minifilter 文件写入/删除/覆盖/截断/重命名/链接目标阻断、SYSTEM-only 设备 ACL，以及带占位 altitude 的 INF/vcxproj。驱动只接受当前服务进程的内核对象、PID、创建时间和 `SeLocateProcessImageName` 实际路径；不提供任意 PID/路径保护接口。
- 已加入 `WindowsSelfProtectionTransport`，服务启动时只尝试打开固定 `\\.\YcszProtection` 设备；设备不存在、状态错误或 IOCTL 失败时，状态保持未启用/失败，不会伪报自保护成功。用户态通过固定盘符到 NT 设备路径转换与共享协议 ABI 对接，未把管理密码传入驱动。
- 已把维护租约接入已认证本地 IPC：管理页的进入/结束维护操作最多 5 分钟，服务侧同时控制 SCM `CanStop`；租约过期由状态机关闭并恢复保护。当前驱动能力报告只包含进程句柄保护和文件过滤，不设置尚未由驱动实现的 `ServiceStop` 能力位。
- 已补 x64 协议布局回归测试（57/57 用户态测试通过）和静态源码门禁；这些结果不等于 WDK 编译、签名、加载或动态阻断验收。
- 本机没有 Windows WDK/签名渠道/隔离 Windows 靶场。本轮没有编译、安装、加载或发布驱动，没有启用测试签名或改变 Secure Boot/HVCI。待完成：WDK 编译与 CAT/正式签名、隔离机加载、非维护状态下终止/删除/重命名/覆盖测试、正常维护更新/卸载/回滚和重启兼容性证据。
