## Windows 构建与自动测试执行路线

- 当前本机 macOS，没有 WDK；不能因此只停留于源码。GitHub `luolisen/ycsz-ufw` 已认证，已有 `.github/workflows/windows-build.yml`。
- 用户已授权上传云端与发布。可以建立 `codex/` 开发分支、提交相关源码并推送用于独立 Windows CI，不 force-push，不修改已有分支历史，不夹带凭据或无关文件。先核对当前差异及远程状态，代码与日志要可追溯。不要在本阶段正式发布或部署未验收驱动。
- 微软目前的官方 NuGet/CI 方案可用于独立 Windows runner。已查询：WDK/SDK 10.0.28000.2526，微软样例使用 windows-2025-vs2026；请核对实际可用性后固定版本。参考 https://learn.microsoft.com/en-us/windows-hardware/drivers/install-the-wdk-using-nuget 和 https://github.com/microsoft/Windows-driver-samples/blob/main/.github/Build-with-GitHub.md 。样例 Directory.Build.props 使用 WDK.x64、SDK.CPP.x64、SDK.CPP 三个包。
- 自动运行真实 Windows PowerShell 解析、应用编译/回归、WDK 与 InfVerif，读失败日志并修复直至通过。保持 unsigned 构建与正式签名/加载分开；CI 不等于生产 Windows 桌面验收。
- 核心新增逻辑必须有针对性测试：卸载状态、租约/会话失效、驱动响应伪造/截断、更新失败回滚。`python3 scripts/test-driver-control.py` 可继续用，但明确它不模拟 Windows 内核。
- 隔离 Windows 动态验收需实际可恢复的专用环境及合法可加载的签名驱动。先探索现有条件，不在生产机器上试验未验证内核代码。正式签名所需身份/证书/微软账户不可伪造；如果确实缺少，清晰列出已尝试路线和唯一必要外部条件，同时继续所有不依赖它的功能。
